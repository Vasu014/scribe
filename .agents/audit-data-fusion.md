# Correctness audit — Persistence / FusionKit / ScratchpadKit

**Scope:** `Packages/MeetingKitCore/Sources/{Persistence,FusionKit,ScratchpadKit}` audited against
SPEC §4.3–§4.6, plus the call sites that make those layers wrong (SessionCoordinator, ScribeApp,
HistoryWindowController). Read-only; the live store at `~/Library/Application Support/Scribe/store.sqlite`
was inspected with `sqlite3 -readonly` and not modified.

**Verdict.** The GRDB layer itself is the strongest part of this codebase — schema, upsert semantics,
`Codable` shapes, UTC date round-trip (verified against the live DB), transaction scoping, manual
cascade delete and the indices on every queried column are all correct, and the ≤5 s cadence for
segments and fragments is genuinely beaten (both are written on emission/debounce, not on a timer).
The defects are on both sides of it. Above the store: the app **silently downgrades to an in-memory
store** when the real one fails to open or migrate, so a migration failure on the very DB this audit
was asked about turns Scribe into a shredder for that launch with no user-visible signal. Inside
FusionKit: the validator — the one component SPEC §4.5 says must never cry wolf — does both, and I
reproduced both: it fires a false hallucination warning on any quote spanning two same-speaker
segments when the other channel has a backchannel between them (the normal case for two-channel
capture), and it silently returns "clean" for any Decision/Action item whose citation is bolded or
absent, which is the majority of what a model actually emits. The provider names a model id
(`claude-sonnet-4-5`) that is not a current Anthropic model, and there is no in-flight guard on
fusion, so the always-enabled Retry button spawns concurrent runs against the same session. The
scratchpad commits text the user deleted. None of these are covered by the 82 tests.

## Smells, not bugs

- `Migrations.swift:16` inserts `meta.schema_version = 1` and nothing ever updates it; a future `v2` migration that forgets the `UPDATE meta` makes the column silently lie. There is no test that asserts `meta` tracks the newest migration.
- Column names drift from the SPEC §4.6 SQL sketch (`startedAt`/`deviceEvents` vs `started_at`/`device_events`). Harmless (the sketch is not normative) but any hand-written SQL taken from the spec will fail.
- `MeetingStore` is a `DatabaseQueue`, so History reads on the main thread serialize behind transcript writes. Fine at dogfood volume; the moment segment volume grows this is a main-thread stall, and `DatabasePool` is the documented answer (see #14).
- `SessionCoordinator.finalizeNonFinalSegments` (`:544-550`) does N single-row writes in N separate transactions instead of one — non-atomic; a crash mid-loop leaves a half-finalized session. Harmless because `isFinal` is currently always `true` on emission (`WhisperKitTranscriber.swift:338`).
- `AnthropicFusionProvider` has no `anthropic-beta`/streaming path; SPEC allows non-streaming, but 300 s non-streaming requests at higher `max_tokens` are exactly what the Anthropic docs say to stream.
- SPEC §4.5 says validator failures are "auto-saved to the eval set"; nothing auto-saves — export is manual only (`HistoryWindowController.swift:1028`). The comment on `FusionRunOutcome` (`FusionService.swift:6-8`) claims the auto-save has its inputs, which is true but misleading: there is no auto-save.
- `EvalCase.machineId` (`:207`) writes to `UserDefaults.standard` on first read from whatever thread calls it — fine in practice, but it is a hidden write inside a getter.
- Raw-audio retention (SPEC §4.6) **holds** in this layer: nothing in Persistence/FusionKit/ScratchpadKit ever sees PCM; `WhisperKitEngine` uses the in-memory `transcribe(audioArray:)` path only. The API key never reaches the store, the logs, the markdown export or the eval JSON (only `note.model`/`prompt_version` are carried); HTTP error snippets are Anthropic error bodies and do not echo the key.

## Test coverage gaps

The package's 82 tests cover none of #1–#9, #12, #13, #15–#21. Specifically:

- **No test file exists for `AnthropicFusionProvider` or `KeychainStore` at all** — no request-shape assertion (so the model id, `max_tokens`, header set and body keys are unverified), no HTTP error-path test, no truncation test, no key-vs-network error distinguishability test.
- `NotesValidator` tests (`FusionKitTests.swift:81-146`) only feed well-formed `- [ts] "quote" — text` lines and **same-channel** adjacent segments (`testQuoteMaySpanSegmentBoundaries:112`). Nothing asserts the false-negative side (bolded/absent citations) or the two-channel interleave of #3 — the two properties that decide whether the validator is trustworthy.
- `FragmentComposerTests.testEmptyAndWhitespaceTextIgnored:69` only tests whitespace typed *first*; there is no test for clearing text that was already typed (#6).
- `PersistenceTests` has no migration test against a **pre-existing** database file (every test uses `MeetingStore.inMemory()`), so "is v2 safe on the real store" is currently unanswerable by the suite; and no test asserts `endedAt == nil` semantics for recovered sessions beyond the state scan (`:72`).
- `ServiceTests` has no concurrency test — nothing exercises two overlapping `fuse`/`retryFusion` calls on one session (#5), and `SessionCoordinatorTests` mocks the runner so the real interleaving never happens.
- No test asserts prompt determinism for fragments sharing an effective anchor (#12), and no test covers `extractTitle` on markdown-decorated title lines (#9).
