## Deliverables (Sources/CaptureKit/ + Tests/CaptureKitTests/, add test target)

1. **`SCKCaptureEngine.swift`** — `CaptureEngine` conformance, the real engine:
   - **System audio (SPEC §4.1):** `SCStream` via `SCContentSharingPicker` or
     `SCShareableContent.main` — capture the MAIN display; `SCStreamConfiguration`:
     `capturesAudio = true`, `excludesCurrentProcessAudio = true`,
     `minimumFrameInterval = CMTime(value:1, timescale:1)` (1 fps),
     `width/height = 2`, `showsCursor = false`, `queueDepth = 3`. Video frames are
     discarded on arrival (there is no audio-only SCStream — spec accepts the waste).
     Audio samples arrive as CMSampleBuffer in `stream(_:didOutputSampleBuffer:of:)` —
     convert CMBlockBuffer/CMSampleBuffer PCM → [Float] at the stream's format.
   - **Mic (SPEC §4.1):** AVAudioEngine inputNode tap; voice processing toggle
     (`setVoiceProcessingEnabled`, default ON — spike pending, see #4).
   - **Start order (SPEC §4.1/§7):** SCStream FIRST, then AVAudioEngine (documented
     constant + comment that the Spike-1 matrix {SCStream/engine-first} × {VP on/off}
     validates or flips it, with tested macOS build numbers recorded in comments).
   - **Session clock:** buffers stamped offset-from-session-start using
     `mach_continuous_time` basis (same convention as SessionKit.SessionClock —
     reimplement locally, do NOT depend on SessionKit; note the shared epoch
     convention in a comment).
   - **Downsample to 16 kHz mono Float32:** AVAudioConverter from each source format
     (mic HW format, SCK stream format — often 48k stereo); produce `CapturedSample`
     (existing type).
   - **Device switching (SPEC §4.1):** observe `AVAudioEngineConfigurationChange` +
     route changes; on change: stop tap, rebuild engine graph, restart tap, keep the
     session alive; surface via a callback `onDeviceChange: (() -> Void)?` (the
     coordinator logs the event — T2's `onRelayDeviceChange` seam).
   - **Degradation paths (SPEC §4.1):** Screen Recording permission missing/revoked
     (check `CGPreflightScreenCaptureAccess`/`CGRequestScreenCaptureAccess`) and SCStream
     failure → ONE silent restart; second failure → mic-only (`remoteStreamActive=false`)
     with `onRemoteDegraded: ((String) -> Void)?` callback. Mic permission via
     AVAudioApplication.requestRecordPermission (macOS 14+).
   - All capture-callback work non-blocking (per `CaptureEngine.onAudio` contract):
     buffer conversion can be synchronous-cheap or hop to a utility queue — document.

2. **`PCMConversion.swift`** — pure helpers: `AVAudioPCMBuffer` → `[Float]` mono mixdown;
   `AVAudioConverter` wrapper 16 kHz mono. Unit-testable WITHOUT any engine.

3. **`PermissionStatus.swift`** — pure-ish queries: mic (AVAudioApplication.shared.recordPermission),
   screen (CGPreflightScreenCaptureAccess), each returning an enum; plus async request
   wrappers. No UI.

4. **`Spike1Notes.md`** (Sources/CaptureKit/ or better: `docs/spikes/spike1.md` — create
   dir): the test matrix from SPEC §7 as a checklist with EMPTY results columns
   (8 runs: {SCStream first, engine first} × {VP on, off} × {machine 1, machine 2}),
   the fallback ladder, and instructions. Runtime validation is manual (hardware +
   TCC prompts) — the code compiles headless.

5. **Tests** (`Tests/CaptureKitTests/`, add target to Package.swift): PCMConversion
   only (mono mixdown math, 48k→16k downsampling ratio sanity, silence passthrough,
   non-interleaved stereo mixdown). SCK/AVAE classes themselves get NO unit tests
   (hardware/TCC) — keep them thin behind the protocol.
