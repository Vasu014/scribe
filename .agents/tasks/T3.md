## Deliverables (Sources/TranscribeKit/ + Tests/TranscribeKitTests/, add test target)

1. **Package.swift**: add WhisperKit dependency
   (`.package(url: "https://github.com/argmaxinc/WhisperKit", from: "0.9.0")` — resolve
   to whatever latest 0.x works; if 0.9 missing use `upToNextMajor(from: "0.7.0")`).
   Attach to TranscribeKit target only. Note: first fetch+build is slow (several
   minutes) — budget for it, run it once.

2. **`WhisperEngine.swift`** — a NARROW seam over WhisperKit so the rest of the module
   (and tests) never import WhisperKit directly:
   ```swift
   protocol WhisperEngine: Sendable {
       func transcribeBuffer(_ samples: [Float]) async throws -> [WhisperHypothesis]
   }
   struct WhisperHypothesis { let text: String; let startSeconds: Double; let endSeconds: Double }
   ```
   `WhisperKitEngine` conforms: loads ONE WhisperKit model (model name injected, default
   "small.en"; `usesKeyedModels`/vocab etc. as needed), and runs
   `transcribe(audioSamples:language:)`-style batch API per buffer. Configure for NO
   temporary audio/cache writes where WhisperKit exposes options (SPEC §4.2 no-temp-audio
   rule; document any option you must leave default and why).

3. **`WhisperKitTranscriber.swift`** — `Transcriber` conformance (SPEC §4.2 architecture):
   - ONE engine instance shared; TWO serial inference queues (one per channel) — e.g. an
     actor per channel delegating to the shared engine, or a locked per-channel
     operation queue. Two model instances are explicitly rejected (SPEC §4.2).
   - Audio is chunked into VAD-ish windows before inference: a simple energy-based VAD
     (RMS threshold + hangover) is acceptable for the seam — target finalization ~3–5 s
     after speech ends: accumulate speech samples, emit a buffer when ≥800 ms of silence
     follows ≥1 s of speech (constants documented, tunable).
   - Segment UUID stability (SPEC §4.2 hard rule): the id is minted at FIRST hypothesis
     for a window; if the engine re-emits a revision for the same window (same
     startSeconds), reuse the id (keep a small per-channel LRU of window→id).
   - `isFinal = true` on first emission for v0 (no re-decode loop; WhisperKit is batch —
     document that revision-based `isFinal=false` paths exist for Phase 2).
   - `inferredAt` stamped at inference completion; offsets derive from the chunk's
     sessionOffset + window position within the accumulated buffer (mind 16 kHz
     sample-count math; document).

4. **`ModelDownloadManager.swift`** — progress-reporting model fetch: WhisperKit's
   model management (`ModelContainer`/`download` API or direct `ModelRegistry` — use
   what your resolved version offers) to fetch a named model into
   `~/Library/Application Support/Scribe/models/`. AsyncStream<Double> progress (0–1),
   completion with the local folder. This is best-effort plumbing: if the resolved
   WhisperKit version's download API differs materially, keep the surface
   (name → progress stream → local path) and mark internals.

5. **Tests** (`Tests/TranscribeKitTests/`, add target): use a FAKE WhisperEngine (no
   model download in CI):
   - windowing: silence is dropped; a 2 s speech burst followed by 800 ms silence emits
     exactly one buffer whose text/offsets round-trip into a TranscriptSegment.
   - stable ids: two hypotheses from the same window share the UUID; a different window
     mints a new id.
   - serial-queue exclusivity: a slow fake engine called on both channels never runs
     two inferences concurrently (record concurrent-entry count with an instrumented
     fake that sleeps).
   - offsets: 16 kHz math sanity (chunk at sessionOffset 10 s + 1.5 s into buffer →
     startOffset ≈ 11.5 s).
