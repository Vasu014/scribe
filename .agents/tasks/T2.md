# Task T2 — SessionKit: SessionCoordinator (session lifecycle + crash recovery)

Read AGENTS.md first, then SPEC.md §4.4 (SessionKit), §3.2 (data flow), §5 (derived UI
states). Implement T2 only; do not touch App/, other modules beyond what's specified.

## Context you inherit
- `Persistence.MeetingStore` — sessions/segments/fragments/notes CRUD + upserts +
  `sessionsInState(.recording)` (crash-recovery scan) + `appendDeviceEvent`.
- `CaptureKit.CaptureEngine` (protocol) + `StubCaptureEngine` (emits silence).

- `SessionKit.SessionDisplayState` already exists (derived UI states).

## Deliverables (Sources/SessionKit/ + Tests/SessionKitTests/ — create the test dir;
add the test target to Package.swift)

1. **`SessionClock.swift`** — session clock per SPEC §4.1: `mach_continuous_time`-based
   monotonic clock started at session begin; `nowOffset() -> TimeInterval`; wall-clock
   start stored by the coordinator on the session row. Two clocks, two jobs: this one
   stamps audio offsets; elapsed displays come from wall clock (doc comment it).

2. **`SessionCoordinator.swift`** — the composition root wiring (SPEC §3.1 note: it
   orchestrates; DATA STILL FLOWS THROUGH THE STORE — the coordinator routes events to
   the store, never between modules directly beyond the injected engines):
   - `init(store:captureEngine:transcriber:lookback:)` (lookback default 20).
   - `start() async throws -> SessionRecord`: create session row, start clock, wire
     capture → per-channel transcription streams → persist segments (upsert on stable
     UUID) within the 5s cadence (batch/persist immediately per finalized hypothesis is
     fine — never hold only in memory), start capture engine.
   - `stop() async`: flush pending fragments (composer flush if attached), finalize
     pending segments (mark non-final segments final or leave — document choice), stop
     engine, set session state `.processing`, then run fusion via injected fusion
     factory (`fusionRunner: @escaping (SessionRecord) async -> FusionRunOutcome` or a
     small protocol — pick one, document why), apply outcome: success → `.complete`;
     findings → stays `.processing` with findings surfaced via state; failure → stays
     `.processing` with error surfaced. Emit coordinator state changes via
     `AsyncStream<CoordinatorEvent>` or callback set — define `CoordinatorEvent`
     (e.g. stateChanged(SessionDisplayState), deviceEventLogged, fusionFindings([…])).
   - **Crash recovery on init**: scan `sessionsInState(.recording)`; for each, mark
     `recovered = true`, state `.processing` (fusion offer), surface a
     `recoveredSessions([SessionRecord])` event. No auto-fusion.
   - **Interruptions**: expose `handleDeviceChange()` (pause/rebuild/resume semantics =
     log `deviceChanged` event + notify engine; the real engine does the rebuild —
     coordinator logs and relays), and `handleSleep()/handleWake()` logging events
     (`sleep`, `wake`) — clock keeps running (SPEC §4.1/§4.4).
   - `retryFusion() async` for sessions stuck in processing after failure.
   - Elapsed time for UI: wall-clock from `session.startedAt` (provide
     `elapsed() -> TimeInterval` while recording).

3. **`TranscriptPipeline.swift`** (may live inside coordinator file if small) —
   capture callback → split by channel → two `AsyncStream<AudioChunk>` (one per
   channel) → `transcriber.transcribe(stream:)` per channel → for each emitted
   `TranscriptSegment` upsert `SegmentRecord` (via store) — persist immediately on
   every hypothesis (beats the ≤5s cadence; document that).

4. **Tests** (`Tests/SessionKitTests/SessionCoordinatorTests.swift`):
   - start/stop happy path with StubCaptureEngine + mock transcriber (emits a couple of
     segments) + mock fusion runner (.success) → session `.complete`, note inserted
     (via store), segments persisted, display events observed.
   - fusion failure → session stays `.processing`, error surfaced, retryFusion succeeds
     later (mock flips result).
   - crash-recovery: create a session in `.recording` directly in the store, init a
     coordinator → event lists it, row now `recovered`, state `.processing`.
   - device-change + sleep/wake events land in `sessions.deviceEvents`.
   - A determinism test for SessionClock offsets (monotonic non-decreasing).
