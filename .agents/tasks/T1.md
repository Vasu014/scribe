# Task T1 — FusionKit: fusion service, Anthropic provider, eval-case builder

Read AGENTS.md first, then SPEC.md §4.5 (FusionKit) and your TASKS.md T1 row. You are
implementing T1 only. Do not touch App/, other modules, or unrelated files.

## Deliverables (all in Packages/MeetingKitCore/Sources/FusionKit + Tests/FusionKitTests)

1. **`SystemPrompt.swift`** — the v1 system prompt text as a Swift constant, with a doc
   comment stating that editing it bumps `PromptVersion.current` to a new value (SPEC §4.5
   prompt-versioning rule). The prompt must specify the fixed output format:
   `Title:` (≤8 words) / Summary (2–4 sentences) / Key points grouped by topic /
   Decisions and Action items — each of the last two as:
   `[MM:SS] "verbatim transcript quote (5–15 words)" — item text (owner if inferable)`.
   Grounding rules to include: only state what the transcript supports; fragments
   ([USER NOTE @ …] lines) indicate what mattered to the user; quote verbatim from the
   transcript; never invent timestamps; if the scratchpad is empty, produce notes from
   the transcript alone (zero-fragment mode).

2. **`KeychainStore.swift`** — minimal wrapper over Security framework
   (`SecItemAdd`/`SecItemCopyMatching`/`SecItemUpdate`/`SecItemDelete`) for a single
   generic-password item holding the Anthropic API key. Service name "com.example.scribe"
   (placeholder bundle id, noted in comment), account "anthropic-api-key". kSecUseDataProtectionKeychain.
   Errors typed and thrown; no force-unwraps. Mark the class as usable from the App target.

3. **`AnthropicFusionProvider.swift`** — `FusionProvider` conformance using URLSession
   against `https://api.anthropic.com/v1/messages` (x-api-key header from KeychainStore,
   anthropic-version 2023-06-01, model id constant "claude-sonnet-4-5", max_tokens 4096,
   temperature passed through — callers use 0.2). No third-party HTTP deps. Failures map
   to typed errors (network, httpStatus, decoding). No API call in unit tests — the
   network layer is behind the `FusionProvider` protocol so tests use a mock.

4. **`FusionService.swift`** — orchestrates one fusion run (SPEC §4.5 + §3.2):
   `fuse(session:lookback:provider:)` reads inputs from `MeetingStore` via injected
   closures or a store instance, assembles prompts (`PromptAssembler` +
   `CanonicalRendering`), calls the provider, extracts/sanitizes the title
   (`PromptAssembler.extractTitle`), runs `NotesValidator.validate`, stores the note via
   `store.insertCanonicalNote`, and updates the session title + state on success. On
   validator findings or provider failure: leave the session in `processing`, record the
   error (returned to caller for the Retry UI), and if validator findings exist still
   store the note but return the findings (SPEC §4.5: failures are surfaced in UI and
   auto-saved to eval set). Also expose `chunkIfNeeded` long-meeting chunking (SPEC §4.5
   operational rules): split transcript at ≥25k words by largest VAD gaps (largest
   `startOffset` deltas) into per-chunk summaries then a final compose — implement the
   splitting + compose-call sequencing behind the same provider; unit-test the splitting
   logic with synthetic segments (no network).

5. **`EvalCase.swift`** — Codable model matching SPEC §4.5 eval-case JSON exactly
   (schema_version 1, prompt_version, model, session_id, session_started_at, title,
   transcript[], fragments[], output, corrected_output?, validator_result, exported_at,
   machine_id) + a builder `EvalCase.build(...)` reading from store records, and
   `machineId` — a stable per-install id persisted to UserDefaults (generate UUID once).
   Unit-test round-trip Codable against a pinned JSON fixture string.

6. **Tests** (`Tests/FusionKitTests/ServiceTests.swift` or similar) — using a mock
   `FusionProvider` returning canned markdown: success path (note stored canonical,
   title updated, session → complete), provider-failure path (session stays processing,
   error surfaced), validator-findings path (note stored, findings returned), chunking
   split test, eval-case round-trip test. Use `MeetingStore.inMemory()`.
