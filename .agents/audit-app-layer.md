# App-layer correctness audit

Audited the working tree (not HEAD — `git diff` shows ~3.3k uncommitted lines across
`App/`, another agent is editing live) on 2026-08-19: every file in `App/`, plus
`Info.plist`, `Scribe.entitlements`, `project.yml`, read against SPEC §4.1–§4.6 and §5.
**Verdict: the AppKit layout/lifecycle work is genuinely careful — the previously-burned
classes (TAMIC, `alignment: .width`, TextKit stacks, `URL.path()`, unfinished
continuations, `terminateLater` run-loop modes) are all fixed and correctly explained —
but the layer still loses user data and user actions quietly.** The dominant remaining
defect class is not AppKit at all: it is *failures the user is waiting on that resolve to
an OSLog line and nothing else*. Three of them (store fallback to in-memory, a
Whisper model that can never be downloaded once setup completes, menu-bar Start
throwing into a log) can each cost a whole meeting with no on-screen signal. Two are
lost-input/animation-race defects in the scratchpad, one is a timer that never stops.
Two hypotheses I expected to confirm were **refuted by evidence** and are not in the
table: the `NSApplication.delegate` is `weak`, but the Release binary's `_main`
(`otool -tvV`, `/tmp/scribe-dd-audit-rel`) releases the delegate *after* `app.run()`, so
the delegate is not deallocated; and the wizard's "Continue" gate is not dead — `makeFooter`
re-reads `modelState` after the step is built. Everything below states the sequence and
the resulting wrong behavior; where I could not construct one I said so.

## Smells, not bugs

- `App/ScribeApp.swift:256-311` — `eventTask = Task { … }` captures `self` **strongly**
  (`Task.init` is `@_implicitSelfCapture`, and only `coordinator` is in the capture list),
  so delegate → task → delegate. Harmless because the delegate is the app, but it is the
  one place in `App/` that does not use `[weak self]`, and the pattern is copy-paste bait.
- `App/ScribeApp.swift:577-583` — the only strong reference to the delegate is a local in
  `main()` while `NSApplication.delegate` is `weak`. The Release binary keeps it alive
  across `run()` (verified), so this is not a bug today; it is one optimizer decision away
  from being one. A `static let` would make it unconditional.
- `App/HistoryWindowController.swift:548-582`, `606-623` — every `reload()` does synchronous
  GRDB reads on the main thread, N+1 (`canonicalNote` per session) plus three more for the
  render key, at 1 Hz while a row is fusing. Fine at v0 sizes; the file's own "do not invest"
  note covers it.
- `App/ScratchpadPanelController.swift:1011-1040` — `syncTimers()` creates the heartbeat and
  then immediately invalidates it whenever the panel is visible but not recording (the
  `else` of the *second* `if` also owns the heartbeat). Behaviourally inert (the handler
  early-returns on `!isRecording`) but the intent is unreadable.
- `App/ScribeApp.swift:64-67` — the `-uiGallery` branch returns *before* the single-instance
  guard, so a gallery launch can put a second status item on screen beside a live recording
  instance. Dev tooling only.
- `Packages/…/SessionCoordinator.swift:617-646` — the event backlog is replayed only to the
  first subscriber, which is whichever surface `ScribeApp` builds first (currently the menu
  bar). `HistoryWindowController.swift:1111-1114` documents that it copes by reading the
  store. Correct today, silently order-dependent.
- `App/MenuBarController.swift:119-125` — `.receive(on: RunLoop.main)` delivers only in
  `.default` mode, so the Sparkle enablement flip is deferred while a menu is being tracked.
  Cosmetic.
